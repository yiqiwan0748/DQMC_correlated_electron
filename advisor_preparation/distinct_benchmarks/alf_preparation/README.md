The minimal build uses GNU Fortran, make, Python3 and compatible BLAS/LAPACK. MPI and HDF5 are optional according to the [pinned build instructions](https://github.com/ALF-QMC/ALF/blob/f4c500cc5d7bcf089400c63e4e75382c558a4ed3/README.md). The candidate starts with **serial noMPI**, one OpenMP/BLAS thread and no HDF5. ALF's [configure script](https://github.com/ALF-QMC/ALF/blob/f4c500cc5d7bcf089400c63e4e75382c558a4ed3/configure.sh) uses `gfortran`, Fortran2008 flags and `-llapack -lblas -fopenmp` for GNU; it checks the numerical-library link before building. Appending `-fno-fast-math` makes the intended floating-point setting explicit. A later MPI build would require a compiler-compatible `mpifort` and MPI runtime, but the four-site comparison needs none.

The actual ISAAC GNU and BLAS/LAPACK module versions have **not** been inventoried. They must be recorded before choosing a compiler pin. The university's [current software guide](https://oit.utk.edu/hpsc/overview/available-software/) requires coherent compiler/library toolchains and describes `module avail/list/show`. Its separate PE-gnu instructions are explicitly for ISAAC Legacy and must not be copied as an ISAAC-NG module prescription. The existing Julia depot does not establish availability of a Fortran development toolchain or the `libblas`/`liblapack` linker names.

A bounded setup pilot uses one CPU,3500MB and20minutes, with a15-minute build timeout. `setup_candidate.sh` defaults to **inventory only**, writes a new receipt directory and exits. The operator reviews that inventory and selects an actual coherent module set, then uses a *different new directory* for explicit build mode. The build clones only the2.6 branch, checks out the pinned commit, records its full Git tree, configures GNU/noMPI/STAB3 without HDF5, builds program and analysis binaries, and saves compiler flags, logs, binary hashes and dynamic-library linkage. It never runs `ALF.out` and can only report `SETUP_BUILT_NOT_BENCHMARKED`.
